# ADR 001: Выбор Игрового Движка

## Контекст
Продюсер заказал разработку воксельной игры (а-ля Minecraft/Hytale) на языке Rust с использованием ИИ, с требованием обеспечить минимальную деградацию кода со временем.

## Решение
Был выбран **Bevy Engine**.

## Обоснование
1. **ECS Архитектура:** Bevy принудительно заставляет разделять данные (Component) и логику (System). Это не позволяет ИИ-агентам создавать огромные "классы-монолиты", свойственные объектно-ориентированному коду. Каждая новая фича (например, гравитация) добавляется как независимая система, не трогая старый код.
2. **Rust-Native:** Движок написан на Rust, что гарантирует высокую производительность и безопасность памяти.
3. **Мультиплеер-ready:** Архитектура ECS идеально ложится на клиент-серверную модель (можно запускать логику без рендера).

## Последствия
Все агенты обязаны писать логику ТОЛЬКО в виде Bevy Systems. Использование глобальных изменяемых переменных (вне Bevy Resources) строго запрещено.
