# ADR 003: Строгая Типизация Координат и Data-Driven Блоки

## Контекст
В воксельных движках самой частой причиной багов является путаница между мировыми (f32/Vec3), глобальными блочными (i32/IVec3), чанковыми (i32/IVec2) и локальными внутри чанка (u8/u16) координатами.
Также хардкодинг свойств блоков (цвета, прозрачности) в коде ведет к частым рекомпиляциям и риску сломать ядро при добавлении контента.

## Решение
1. Введен модуль `coordinates.rs` с типами `WorldPos`, `ChunkPos`, `LocalBlockPos`. Запрещено использовать "голые" типы (Vec3, IVec3) для логики вокселей.
2. Введен модуль `blocks.rs` (BlockRegistry). Свойства блоков загружаются из файла конфигурации `assets/blocks/base.ron`.

## Последствия
- Компилятор Rust автоматически блокирует неправильную передачу координат.
- ИИ-агенты (особенно `gameplay_coder` и `game_designer`) должны добавлять блоки только редактируя `.ron` файлы, а не исходный код. Код отвечает только за рендер и физику, но не знает о конкретных блоках ("земля", "камень").
