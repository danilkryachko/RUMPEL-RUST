# Game Design Document (GDD)
**Проект:** RUMPEL RUST
**Жанр:** Voxel Sandbox (Minecraft / Hytale-like)

Этот документ является живым. Агент-Геймдизайнер обязан поддерживать его в актуальном состоянии по мере добавления новых фич.

## 1. Базовые механики (Core Loop)
Игрок появляется в процедурно сгенерированном мире, состоящем из блоков. Основной цикл: 
Исследование -> Добыча ресурсов -> Строительство.

## 2. Мир и Генерация
* **Блоки:** Кубы размером 1x1x1 метр. 
* **Чанки:** Runtime-рендер и стриминг мира используют чанки `bevy_voxel_world` 32x32x32. Доменный слой RUMPEL RUST сохраняет типизированные координаты и может иметь собственные правила вертикального диапазона поверх backend-чанков.
* **Генерация:** Шум Перлина для создания биомов (равнины, горы). Под землей — пещеры.

## 3. Игрок
* Вид от первого лица (позже от третьего).
* Игрок имеет хитбокс 1.8x0.8x0.8.
* Движение: Ходьба, Бег, Прыжок. Позже будет добавлен режим полета (Creative mode).

## 4. Будущие Фичи (Roadmap)
1. **Разрушение/установка блоков:** Игрок может удалять блок перед собой (ЛКМ) и ставить блок из инвентаря (ПКМ).
2. **Освещение:** Простые тени и затенение (Ambient Occlusion) для вокселей.
3. **Мультиплеер:** Синхронизация чанков и игроков по сети.

## 5. Моддинг
* **Ядро:** Rust отвечает за производительные и безопасные системы: чанки, ECS, рендер, генерацию мира, сохранения.
* **Данные:** Базовые блоки живут в `assets/blocks/base.ron`.
* **Скрипты:** Lua-моды живут в `assets/mods/*.lua` и подключаются через `rumpel_modding`.
* **Первый API:** `register_block({...})` позволяет модам добавлять новые блоки до генерации мира.
* **Будущее API:** события блоков, рецепты, NPC, квесты и игровые правила должны добавляться через явные безопасные функции, без прямого доступа к памяти чанков.
